# 06. 테스트, 환경 변수 및 Vercel 배포

## 환경 변수
`.env.example` 파일에 변수 이름만 제공하고 실제 값은 커밋하지 않는다.

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
```

- `OPENAI_API_KEY`: OpenAI API 키
- `OPENAI_MODEL`: 사용할 수 있는 모델 ID
- `SUPABASE_URL`: Supabase 프로젝트 URL
- `SUPABASE_SERVICE_ROLE_KEY`: 서버 전용 키

## 로컬 실행 기준
1. Node.js LTS 설치
2. 프로젝트 루트에서 `npm install`
3. `.env.example`을 복사해 `.env` 생성
4. 본인의 키와 URL 입력
5. `npm run dev`로 로컬 서버 실행
6. 브라우저에서 로컬 주소 접속
7. API 요청과 브라우저 개발자 도구의 오류 확인

실제 실행 스크립트는 프로젝트 구현 시 `package.json`에 정의한다. Vercel Functions와 동일한 실행 방식을 사용하도록 Vercel CLI의 로컬 개발 명령을 권장한다.

## 기능 테스트 체크리스트

### 식재료
- [ ] 재료 입력 후 추가 버튼으로 추가된다.
- [ ] Enter 키로도 추가된다.
- [ ] 공백 입력은 거부된다.
- [ ] 중복 재료는 중복 등록되지 않는다.
- [ ] 재료별 삭제가 동작한다.
- [ ] 20개 초과 시 안내한다.

### AI 추천
- [ ] 재료 없이 요청하면 차단된다.
- [ ] 정상 입력이면 최대 3개 레시피가 표시된다.
- [ ] 보유 재료와 추가 재료가 구분된다.
- [ ] 제외 재료가 추천에 포함되지 않는다.
- [ ] 요청 중 로딩 상태와 중복 클릭 방지가 동작한다.
- [ ] OpenAI 키 누락/잘못된 키/네트워크 실패 시 친절한 오류가 표시된다.
- [ ] 브라우저 코드와 응답에서 API 키가 노출되지 않는다.
- [ ] 잘못된 AI JSON 응답은 안전하게 실패 처리된다.

### 피드백
- [ ] 로그인 없이 피드백을 제출할 수 있다.
- [ ] 5자 미만 및 500자 초과 입력이 거부된다.
- [ ] 유형 선택 검증이 동작한다.
- [ ] 저장 성공 시 Supabase에 행이 생성된다.
- [ ] 저장 성공 후 목록이 최신순으로 갱신된다.
- [ ] 저장 실패 시 작성 내용이 유지된다.
- [ ] 피드백이 HTML로 실행되지 않고 텍스트로 표시된다.
- [ ] 목록은 최대 50개이며 최신순이다.

### UI 및 접근성
- [ ] 360px 너비에서 가로 스크롤이 없다.
- [ ] 태블릿과 데스크톱에서 레이아웃이 자연스럽다.
- [ ] 키보드로 주요 기능을 사용할 수 있다.
- [ ] 입력 label과 포커스 표시가 있다.
- [ ] 로딩/오류/빈 상태가 구분된다.

## Vercel 배포 순서
1. 프로젝트를 Git 저장소에 올린다. `.env`는 제외한다.
2. Vercel에서 저장소를 Import한다.
3. 프로젝트 설정에서 필요한 Node.js 런타임을 확인한다.
4. Vercel Project Settings → Environment Variables에 네 가지 환경 변수를 등록한다.
5. Production, Preview, Development 환경 적용 범위를 확인한다.
6. 배포를 실행한다.
7. 배포 URL에서 AI 추천과 피드백 저장/조회 기능을 실제로 테스트한다.
8. 실패하면 Vercel Function Logs에서 원인을 확인하되 비밀값이 로그에 출력되지 않는지 점검한다.

## 배포 완료 기준
- 배포 URL 접속 가능
- 정적 화면 정상 표시
- `/api/recipes` 정상 응답 또는 명확한 오류 응답
- `/api/feedback` 저장 및 조회 성공
- 환경 변수 누락 시 비밀값 없이 설정 오류 안내
- 모바일 화면 정상
- 브라우저 개발자 도구에 치명적인 오류 없음

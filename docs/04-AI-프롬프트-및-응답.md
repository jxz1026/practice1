# 04. AI 프롬프트 및 응답 규격

## 목적
AI가 단순히 그럴듯한 문장을 만드는 대신, 화면에서 바로 사용할 수 있는 일관된 레시피 데이터를 반환하도록 한다.

## 시스템 지시문 초안
```text
너는 냉장고 속 식재료를 활용하는 한국어 요리 도우미다.
사용자가 보유한 재료를 최대한 활용해 현실적으로 만들 수 있는 요리를 최대 3개 추천한다.

규칙:
1. 보유 재료 목록에 있는 재료를 우선 사용한다.
2. 보유 재료와 추가 구매가 필요한 재료를 분리한다.
3. 제외 재료는 어떤 형태로도 레시피에 넣지 않는다.
4. 입력에 없는 재료를 보유 재료라고 표현하지 않는다.
5. 각 레시피는 3~8개의 구체적인 조리 단계로 작성한다.
6. 조리 시간은 준비와 가열을 포함한 대략적인 분 단위로 작성한다.
7. 난이도는 쉬움, 보통, 어려움 중 하나로 작성한다.
8. 한국어로 간결하고 초보자도 이해하기 쉽게 작성한다.
9. 알레르기 및 식품 안전을 보증하지 않는다. 필요한 경우 주의사항에 식품 라벨 확인, 교차오염 방지, 충분한 가열을 안내한다.
10. 결과는 지정된 JSON 스키마에 맞춘다. JSON 바깥에 문장을 쓰지 않는다.
```

## 사용자 입력 구성
서버는 다음 항목을 프롬프트에 전달한다.
- 보유 식재료 배열
- 인원수
- 조리 시간 제한
- 제외/주의 재료 배열
- 선호 조건

사용자 입력은 신뢰할 수 없는 데이터로 취급한다. 입력값이 시스템 지시문을 바꾸도록 허용하지 않는다.

## 출력 JSON 스키마
```json
{
  "recipes": [
    {
      "name": "문자열",
      "description": "문자열",
      "cookingTime": 15,
      "difficulty": "쉬움",
      "usedIngredients": [
        {"name": "문자열", "amount": "문자열"}
      ],
      "extraIngredients": [
        {"name": "문자열", "amount": "문자열"}
      ],
      "steps": ["문자열", "문자열", "문자열"],
      "cautions": ["문자열"]
    }
  ]
}
```

## 서버 검증 규칙
- `recipes`는 배열이며 1~3개
- `name`, `description`은 비어 있지 않은 문자열
- `cookingTime`은 1~240 정수
- `difficulty`는 허용된 세 값 중 하나
- `usedIngredients`, `extraIngredients`는 배열
- 재료 객체는 `name`, `amount` 문자열 포함
- `steps`는 3~8개의 문자열
- `cautions`는 문자열 배열
- 스키마 불일치 또는 파싱 실패 시 사용자에게 재요청 안내

## AI 호출 원칙
- OpenAI API 키는 서버 환경 변수 `OPENAI_API_KEY`에서 읽는다.
- 모델명은 환경 변수 `OPENAI_MODEL`로 관리해 코드에 고정하지 않는다.
- 서버에서만 OpenAI SDK를 호출한다.
- API 타임아웃과 실패 처리를 구현한다.
- AI 응답 원문 전체를 브라우저에 노출하지 않는다.
- 사용량과 비용을 고려해 한 번의 요청에 최대 3개 결과만 생성한다.

## 안전 안내 문구
결과 영역에 다음 취지의 문구를 표시한다.

“레시피는 AI가 생성한 참고 정보입니다. 조리 전 재료의 신선도와 식품 표시를 확인하고, 알레르기 유발 성분 및 교차오염 여부를 직접 확인해 주세요. 조리 환경과 재료 상태에 따라 조리 시간은 달라질 수 있습니다.”

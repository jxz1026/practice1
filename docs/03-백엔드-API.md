# 03. 백엔드 및 API 구현 지침

## 실행 환경
Node.js 기반 Vercel Serverless Functions를 사용한다. 정적 프론트엔드와 `/api` 서버 함수를 같은 프로젝트에서 배포한다.

## 공통 규칙
- 요청 본문 크기를 제한한다.
- `Content-Type: application/json`을 확인한다.
- 입력값 타입과 길이를 서버에서 재검증한다.
- 성공/실패 응답은 JSON으로 통일한다.
- 비밀값과 내부 오류 상세를 클라이언트에 노출하지 않는다.
- 적절한 HTTP 상태 코드를 반환한다.

## API 1: POST /api/recipes
### 요청 예시
```json
{
  "ingredients": ["달걀", "양파", "두부"],
  "servings": 2,
  "timeLimit": 30,
  "excludedIngredients": ["땅콩"],
  "preference": "간단하고 담백하게"
}
```

### 검증
- `ingredients`: 문자열 배열, 1~20개, 각 1~30자
- `servings`: 정수 1~8
- `timeLimit`: 15, 30, 45 또는 `null`
- `excludedIngredients`: 문자열 배열 최대 10개
- `preference`: 문자열 최대 100자
- 제외 재료와 보유 재료가 겹치면 제외 재료를 우선 적용하고 사용자에게 안내한다.

### 성공 응답 예시
```json
{
  "recipes": [
    {
      "name": "두부 달걀 볶음",
      "description": "두부와 달걀을 활용한 간단한 한 끼",
      "cookingTime": 15,
      "difficulty": "쉬움",
      "usedIngredients": [
        {"name": "두부", "amount": "1/2모"},
        {"name": "달걀", "amount": "2개"}
      ],
      "extraIngredients": [{"name": "식용유", "amount": "약간"}],
      "steps": ["두부의 물기를 제거합니다.", "팬에 기름을 두르고 두부를 굽습니다.", "달걀을 넣고 익힙니다."],
      "cautions": ["재료의 신선도와 충분한 가열 여부를 확인하세요."]
    }
  ]
}
```

### AI 지시사항
- 입력된 보유 재료를 우선 활용한다.
- 제외 재료는 레시피와 추가 재료에 포함하지 않는다.
- 보유 재료와 추가 재료를 명확히 구분한다.
- 최대 3개 레시피만 생성한다.
- JSON 외의 설명 문장을 응답에 섞지 않도록 구조화 출력을 사용한다.
- 조리 시간은 현실적인 추정치로 제공한다.
- 식품 안전, 알레르기 안전을 보증하지 않는다.
- 모델이 반환한 JSON을 서버에서 파싱하고 스키마 검증한다.

## API 2: POST /api/feedback
### 요청 예시
```json
{
  "type": "개선 의견",
  "rating": 4,
  "content": "재료를 더 쉽게 입력할 수 있으면 좋겠어요."
}
```

### 검증
- `type`: `칭찬`, `개선 의견`, `오류 신고` 중 하나
- `rating`: 생략 가능, 정수 1~5
- `content`: 문자열 5~500자
- HTML 태그 제거를 보안의 유일한 수단으로 사용하지 않는다. 출력 시 텍스트로 렌더링한다.

### 성공 응답
```json
{"ok": true, "feedback": {"id": 123}}
```

## API 3: GET /api/feedback
- Supabase에서 최신 50개를 조회한다.
- `created_at` 내림차순 정렬
- 공개 목록에 필요한 컬럼만 반환한다.
- 성공 응답: `{"ok": true, "items": []}`

## HTTP 상태 코드
- 200: 조회 성공
- 201: 저장 성공
- 400: 입력값 오류
- 405: 허용하지 않는 메서드
- 413: 요청 크기 초과
- 429: 요청 한도 초과
- 500: 서버 내부 오류
- 502 또는 503: AI 공급자 응답/연결 문제

## 오류 응답 형식
```json
{
  "ok": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "식재료를 1개 이상 입력해 주세요."
  }
}
```

클라이언트에는 사용자에게 필요한 메시지만 반환한다. 상세 오류는 서버 로그에 기록하되 API 키, 전체 프롬프트의 민감한 내용, 사용자 개인정보는 기록하지 않는다.

# 05. Supabase 데이터베이스 및 보안 지침

## 데이터 저장 범위
이번 프로토타입에서 Supabase에 저장하는 데이터는 사용자가 자발적으로 작성한 피드백뿐이다. 식재료 입력값과 AI 추천 결과는 데이터베이스에 저장하지 않는다.

## 테이블: feedback
| 컬럼 | 타입 | 필수 | 설명 |
|---|---|---:|---|
| id | bigint identity | 예 | 기본키 |
| type | text | 예 | 칭찬/개선 의견/오류 신고 |
| rating | int2 | 아니오 | 1~5점 |
| content | text | 예 | 피드백 본문 |
| created_at | timestamptz | 예 | 생성 시각 |

## SQL
```sql
create table if not exists public.feedback (
  id bigint generated by default as identity primary key,
  type text not null check (type in ('칭찬', '개선 의견', '오류 신고')),
  rating smallint null check (rating between 1 and 5),
  content text not null check (char_length(content) between 5 and 500),
  created_at timestamptz not null default now()
);

create index if not exists feedback_created_at_idx
  on public.feedback (created_at desc);

alter table public.feedback enable row level security;
```

## 권장 접근 방식
- 브라우저는 Supabase `service_role` 키를 절대 사용하지 않는다.
- 피드백 저장과 조회는 Node.js 서버 API가 Supabase 서버 클라이언트를 통해 수행한다.
- 서버에는 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`를 환경 변수로 설정한다.
- 서비스 키를 사용하므로 서버 API에서 입력 검증과 호출 제한을 반드시 수행한다.
- 공개 피드백 목록에는 이름/이메일 등 식별 정보를 저장하거나 노출하지 않는다.
- 테이블에 공개 직접 접근 정책을 추가하지 않는다. 서버 API만 사용한다.
- 향후 브라우저에서 직접 접근하는 구조로 바꿀 경우 별도 검토 후 최소 권한 RLS 정책을 만든다.

## 조회 기준
- 최근 50개
- `created_at` 내림차순
- 반환 필드: `id`, `type`, `rating`, `content`, `created_at`

## Supabase 설정 확인
1. Supabase 프로젝트 생성
2. SQL Editor에서 위 SQL 실행
3. Table Editor에서 `feedback` 테이블 생성 여부 확인
4. 프로젝트 URL과 서버용 service role 키 확인
5. 키는 `.env` 및 Vercel 환경 변수에만 입력

## 개인정보 및 운영 주의
- 피드백은 공개 목록에 그대로 표시될 수 있으므로 제출 전에 개인정보 입력 금지 안내를 제공한다.
- 운영 단계에서는 욕설/스팸 대응, 삭제 요청 처리, 보관 기간 정책을 추가 검토한다.
- 공개 피드백에 악성 링크나 스크립트가 있어도 실행되지 않도록 화면에서 `textContent`로 출력한다.

# 02. 프론트엔드 구현 지침

## 기술
HTML5, CSS3, Vanilla JavaScript만 사용한다. 별도 프레임워크는 도입하지 않는다.

## 권장 폴더 구조
```text
/
├─ index.html
├─ styles/
│  └─ main.css
├─ scripts/
│  └─ app.js
├─ api/
│  ├─ recipes.js
│  └─ feedback.js
├─ lib/
│  ├─ openai.js
│  └─ supabase.js
├─ supabase/
│  └─ schema.sql
├─ docs/
├─ AGENTS.md
├─ PRD.md
├─ package.json
├─ vercel.json
├─ .env.example
└─ .gitignore
```

## HTML 기준
- 시맨틱 요소(`header`, `main`, `section`, `form`, `footer`) 사용
- 각 섹션에 제목을 제공
- 입력창은 label과 연결
- 오류/성공 메시지를 표시할 `role="status"` 또는 `aria-live="polite"` 영역 제공
- 사용자 입력을 HTML 문자열로 조립해 삽입하지 않는다.

## CSS 기준
- CSS 커스텀 속성으로 색상, 간격, 모서리 둥글기 관리
- 모바일 우선으로 작성
- 기본 폰트는 시스템 한글 폰트 스택 사용
- 버튼 hover/focus/disabled 상태 구분
- 긴 레시피도 읽기 편하도록 줄 간격과 폭 관리
- 작은 화면에서 가로 스크롤이 생기지 않도록 확인

## JavaScript 기능 모듈
- `addIngredient()`: 재료 추가 및 검증
- `removeIngredient(name)`: 재료 삭제
- `renderIngredients()`: 재료 칩 렌더링
- `getRecipeRecommendations()`: `/api/recipes` 호출
- `renderRecipes(recipes)`: 결과 카드 렌더링
- `copyRecipe(recipe)`: 레시피 텍스트 복사
- `submitFeedback()`: 피드백 저장 API 호출
- `loadFeedback()`: 최신 피드백 조회
- `showMessage(type, message)`: 공통 상태 메시지

## API 통신
- `fetch` 사용
- JSON 요청/응답을 사용
- `response.ok`를 확인한 후 본문 처리
- 네트워크 예외를 사용자 메시지로 변환
- 버튼 로딩 상태를 `finally`에서 반드시 복구
- 서버가 반환한 메시지를 그대로 HTML로 삽입하지 않는다.

## 프론트엔드 검증
- 빈 재료 추가 불가
- 중복 재료 추가 불가
- 재료 20개 초과 불가
- 1개 미만 재료로 추천 요청 불가
- 피드백 5~500자 검증
- 서버 검증도 별도로 수행하며 프론트 검증만 신뢰하지 않는다.
